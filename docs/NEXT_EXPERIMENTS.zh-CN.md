# 接下来可以做的实验

基础 XDMA、双通道传输和 4 GiB DDR3 数据校验已经跑通。下面这些方向是在现有
工程上继续玩的增量实验；每轮只改一个主要变量，并保存 bitstream SHA-256、
PCIe 拓扑、内核日志和数据校验结果。

## 1. 增加主机可读的 Build ID

当前映像身份通过 bitstream SHA-256 和 JTAG 报告关联。下一版可以在独立
PCIe BAR 中加入只读 magic、版本、Git commit 和构建时间，让 Linux 在写 DDR
前直接核对 FPGA 映像。

DDR 已占用 `0x00000000–0xffffffff` 的完整 32-bit MIG 地址空间，Build ID
不能直接插进现有 DDR 映射。更合适的做法是为寄存器设计独立 BAR，再给验证
脚本加入期望值检查。

## 2. 解释 PCIe 带宽差异

现有 `lspci`/内核估算约 2.0 Gb/s，而 XDMA 工具单次 64 MiB 计时约为
597/563 MB/s。先用多轮连续传输的总字节数和外部墙钟时间建立基准，再分别
替换线缆、雷电盒、M.2 M-Key → PCIe ×4 转接板和主机。理想对照是带原生
PCIe 插槽的 x86-64 主机。

每轮同时记录所有 bridge 和 endpoint 的 `LnkCap/LnkSta`，区分配置字段、
工具内部计时与端到端吞吐。

## 3. 建立吞吐矩阵

在数据比较继续通过的前提下，测试 4 KiB、64 KiB、1 MiB、8 MiB、64 MiB
的 H2C/C2H，并覆盖 channel 0/1。记录请求大小、总字节数、墙钟时间、CPU
占用和路径带宽，最后用中位数和离散程度比较，而不是只保留最高数字。

## 4. 长时间双通道与错误恢复

在两个不重叠的 DDR 地址区间持续运行 channel 0 和 1，观察链路总带宽、
单通道限制和驱动并发行为。可加入受控的进程终止、重新打开设备和驱动重载，
每轮同时保存 dmesg、AER、温度、功耗和错误计数。

## 5. XDMA event、MSI 与用户中断

当前设计使用一个 MSI vector，基础回归记录到了中断计数变化。下一步可以给
event 节点接入一个最小自定义中断源，测量触发、唤醒和用户态响应延迟，并在
压力 DMA 同时运行时观察丢中断或抖动。

## 6. 自定义 AXI 数据面

从独立 AXI BRAM 或 loopback 核开始，再逐步加入：

- 主机到 FPGA 的高速采集与回放；
- 环形缓冲区和 descriptor 管理；
- FPGA 侧预处理后 DMA 回主机；
- 多通道流量整形和硬件时间戳。

这样可以先把协议和驱动接口跑通，再决定是否把真实外设接入 J1–J4。

## 7. Windows 原生 DMA

Windows 已经完成 Vivado、JTAG 和 PCIe 枚举，原生 DMA 还没有验证。驱动获取、
签名以及本仓库选择 Linux 的原因见
[README](../README.zh-CN.md#为什么-dma-放在原生-linux)。拿到与 `10ee:7024`、
系统版本和签名策略匹配的 Windows 驱动后，可以复用 Linux 侧的地址、长度和
数据 pattern，补齐 H2C/C2H 比较与吞吐测试。

## 8. 上电自动配置

当前通过 JTAG 写入易失 SRAM，FPGA 掉电后需要重新配置。后续可以确认板上
configuration flash 型号、连接和启动模式，再建立“生成配置文件 → 写入 →
断电重启 → 回读映像身份 → PCIe 枚举”的独立流程。自动配置应使用带 Build ID
的新映像，便于主机直接确认启动版本。

## 9. 用 Vivado BASIC 重跑构建

本次干净构建使用 Vivado 2026.1 Enterprise 评估许可。AMD 文档列出 7 Series
和 XDMA 对 BASIC 档位的支持，但仓库还没有在 BASIC 环境中实际重跑。可以在
一台只安装 BASIC 许可的干净环境中执行同一个 `fpga/build.tcl`，比较 IP 状态、
实现结果和 bitstream SHA-256。

## 10. J1–J4、W26、R24 与 T20

这些信号不参与当前 XDMA 数据通路：

- J1–J4 可作为后续触发、状态、GPIO 或低速控制入口，使用实测 1.8 V IO
  电平，并保留板型识别下拉的处理；
- W26 的主板功能仍未确认，当前设计不把它设为顶层端口，后续可追踪主板网络
  与控制时序；
- R24/T20 的外接负载和方向还缺少实板证据，确认后再决定是否由 FPGA 驱动。

这部分适合独立成一个 IO 实验工程，避免把未确认的外部信号带进已经稳定的
XDMA/DDR 基线。
