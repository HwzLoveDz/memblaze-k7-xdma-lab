# 后续可以做的实验

当前主机侧功能链已经闭环。每轮实验只改变一个主要变量，并保留 bitstream
SHA-256、PCIe 拓扑、内核日志和数据校验。

## 1. 解释 PCIe 带宽测量差异

现有 `lspci`/内核估算约 2.0 Gb/s，但 XDMA 工具单次 64 MiB 计时约为
597/563 MB/s。先用多次连续传输的总字节数和外部墙钟时间建立基准，再分别
替换线缆、雷电盒、M.2 M-Key ↔ PCIe ×4 转接板和主机。理想对照是带原生
PCIe 插槽的 x86-64 主机。每轮同时记录所有 bridge 和 endpoint 的
`LnkCap/LnkSta`，区分配置字段、工具内部计时与端到端吞吐。

## 2. 建立吞吐矩阵

在数据一致性继续通过的前提下，测试 4 KiB、64 KiB、1 MiB、8 MiB、
64 MiB 的 H2C/C2H，分别覆盖 channel 0/1。记录请求大小、总字节数、耗时、
CPU 占用和路径带宽；不要只挑最高数字。

## 3. 长时间双通道并发与错误恢复

channel 0 和 1 各 64 MiB 的单轮并发写入、回读和比较已经通过。下一步可在
不重叠地址区间持续循环，区分链路总带宽、单通道限制和驱动并发行为，并做
受控的进程终止与恢复。每轮额外记录 dmesg 与 AER，失败时停止两个作业再清理。

## 4. 重复全容量与老化验证

64 × 64 MiB 已覆盖完整 4 GiB，全部 64 块写入、回读和比较通过。后续可在
固定温度、风道和供电条件下重复多轮全容量测试，检查偶发错误和长期稳定性。
每轮都会覆盖整片 FPGA DDR，执行前确认没有其他逻辑使用 DDR。

## 5. 稳定性、温度和功耗

在固定风道下循环数小时的小块和 64 MiB 测试，记录板上温度、电源输入、
AER 计数、XDMA timeout 和错误率。此实验才能回答长期运行稳定性。

## 6. XDMA 中断与 event

验证 MSI/MSI-X、event 节点和用户中断延迟。先做只读寄存器地图和中断源
确认，再加入最小自定义 AXI-Lite 寄存器；不要在定义不明的外部 IO 上输出。

## 7. 映像身份寄存器

在独立 AXI-Lite 地址放置只读 magic、设计版本和构建 ID。Linux 写 DDR 前
读取并核对它，可把当前的人工映像确认升级为机器检查。

## 8. 自定义 AXI 数据面

可以从独立 AXI BRAM 或 loopback 核开始，再尝试：

- 主机到 FPGA 的高速采集/回放；
- 环形缓冲区和 descriptor 管理；
- 简单 FPGA 预处理后 DMA 回主机；
- 多通道流量整形和时间戳。

J1–J4 扩展 IO 可作为后续触发、状态或低速控制入口，但必须使用实测
1.8 V 约束，并单独处理板型识别下拉。W26 在功能未确认前不作为顶层
端口；配置后使用 `Pullnone`，外部保持高阻观察。
